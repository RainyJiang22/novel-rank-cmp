# 小说热榜 — 功能分析

## 概述

新建独立 Kotlin Compose Multiplatform 项目「小说热榜」，目标是在 Android、iOS、桌面端查询起点、番茄、晋江的分类前十作品。首版工程位于独立 `novel-rank-cmp` 仓库，用户已明确移除七猫，当前保留三端、三站。

已确认：按网站、类型查询前十热榜。实现假设：第一版用共享 CMP UI + Python 聚合服务，提供来源跳转、榜单口径、采集时间、刷新、关键词筛选、服务地址配置。各站分类和热度单位保持原样，不做跨站合并排名。网站没有相应分类榜时不把全站榜过滤结果伪装成分类前十。

前序交付阶段（2026-11-03）：**实现 Android、iOS、桌面共享客户端 v0.1.0，并将现有 server API 部署到 47.251.189.239**，现已完成。当前追加范围为移除七猫、修复起点并更新已部署服务，见文末。server v0.1.0 已提供目录、排名、缓存和状态 API。本轮实现共享业务界面、网络、平台配置存储及普通测试，复用现有接口。部署必须保留机器上其他服务，使用独立进程、环境、回环端口与 `/novelrank/` 路由。项目远程为 `https://github.com/RainyJiang22/novel-rank-cmp.git`。

工作流：沿用 `quality_gate=off`；保留共享状态、契约和桌面 UI 自动测试。无新增接口，复用既有 API 测试链验证云端；最终质量验收 `SKIPPED`。

## 一、交互链

### 场景 1：查询分类前十

**用户故事**：作为小说读者或选题者，我想选择网站和类型，查看该类型前十作品及真实来源。

打开应用 → 加载网站目录 → 选择网站 → 选择该站榜单与分类 → 查看排名、书名、作者、热度原始单位 → 点击作品在系统浏览器打开来源。桌面宽屏展示网站侧栏，手机展示横向网站选项。

### 场景 2：刷新和失败重试

**用户故事**：作为用户，我想知道榜单是否新鲜，并在来源暂不可用时看到原因。

点击刷新 → 显示加载进度 → 展示采集时间与缓存标记；若访问受限、页面变化或超时，展示具体状态与来源入口；若存在旧快照，明确标记过期并保留原采集时间。

### 场景 3：连接自己的服务

打开服务设置 → 输入 HTTP(S) 聚合服务地址 → 保存 → 重新加载目录。三端默认 `https://47.251.189.239/novelrank`。本地 Debug 调试可改为桌面/iOS 模拟器 `http://127.0.0.1:8000`、Android 模拟器 `http://10.0.2.2:8000`；真机输入同网段服务地址。Android/iOS Release 只接受 HTTPS。

## 二、逻辑树

### 事件流

| 时刻 | 事件 | 处理 | 新事件 |
| --- | --- | --- | --- |
| T1 | 客户端进入首页 | GET /api/v1/catalog | 网站、分类、榜单目录加载完成 |
| T2 | 更换网站、分类、榜单 | 取消前一请求，验证组合，查询 top10 | 加载、成功或失败 |
| T3 | 服务收到合法请求 | 使用来源适配器与按完整查询键缓存 | 原始来源顺序前十 |
| T4 | 点击刷新 | 绕过新鲜缓存，遵守来源请求间隔 | 最新结果或显式旧快照 |
| T5 | 点击作品 | 校验 HTTP(S) 链接并打开浏览器 | 原站作品页 |

### 状态流转

| 实体 | 触发 | 前状态 | 后状态 |
| --- | --- | --- | --- |
| 客户端页面 | 查询 | 任意 | Loading → Ready / Error |
| 服务榜单 | 来源响应 | 未知 | ok / partial / blocked / unavailable / parse_error |
| 缓存快照 | 刷新失败 | 已存在快照 | stale，采集时间不变 |

### 异常流与回退

| 异常 | 条件 | 用户反馈 | 回退 |
| --- | --- | --- | --- |
| 目录请求失败 | 服务断开或地址错误 | 连接失败、设置地址、重试 | 不填充假数据 |
| 来源访问受限 | 验证页面、202/403/429 | 来源受限 | 原站链接、有限期旧快照 |
| 解析失效 | 预期容器或分类不匹配 | 页面结构变化 | 不返回成功空榜 |
| 作品不足十条 | 来源真实返回少于十条 | 已获取 N/10 | 保留原名次，不补齐 |
| 元数据乱码/部分失败 | 书名为私有区字符等 | 部分数据可用 | 保留来源位置并说明字段缺失 |
| 快速切换 | 旧请求晚返回 | 保持当前筛选结果 | 取消旧请求并校验请求身份 |

## 四、结论

服务端契约已经完成；本轮先实现客户端模型、网络和平台配置，再实现选择/请求状态与共享 UI，最后执行普通测试和桌面联调。复杂度集中在站点结构变化、乱码、分类与榜单口径匹配。暂不实现章节抓取、登录付费内容、验证码处理、跨站统一热度、账号体系、后台持续扫榜和历史趋势。

## 2026-11-03 追加：来源修复与移除七猫

起点 PC 页面返回 202 探测脚本，官方移动端公开月票/畅销榜经本地与云端普通 GET 可用。改为解析公开 SSR JSON，校验榜单、分类、当月、页码和原始名次，保留现有 API 参数和 14 类；畅销数值未公开，返回 null。

七猫云端 405 为对方 WAF 拦截，用户明确决定移除：删除目录、适配器、网络白名单和探测项；三端从目录显示三个网站，旧七猫请求在网络前返回 400。当前文案和测试同步更新，历史验证记录保留。

修复只更新 NovelRank release 并重启 `novelrank.service`，核对原服务状态。保留客户端已有 `ServiceAddress.kt` 格式改动，不自动提交/推送，不执行 Android/iOS 原生构建。普通后端、共享客户端测试和云端 API 链路照常执行；最终质量验收仍为 SKIPPED。
